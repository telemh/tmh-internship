# Итоговая защита · 30–45 минут

1. 5–7 минут: студент запускает проект и показывает основной сценарий.
2. 10 минут: объясняет поток данных, один крайний случай и выбранное архитектурное решение.
3. 10–15 минут: небольшое изменение на своём коде с тестом. Объём не должен требовать новой технологии.
4. 5–10 минут: review изменения, ограничения и дальнейший план обучения.

| Направление | Пример изменения в пределах освоенного |
| --- | --- |
| Mobile | Добавить фильтр source; сохранить его при возвращении в экран |
| Backend | Изменить default limit и доказать корректный total |
| Frontend | Добавить сохранение kind в URL без гонки запросов |
| Интеграции | Добавить один новый синтетический статус и ошибочный fixture |
| AI / RAG | Добавить справочный документ и показать согласованное перестроение |
| DevOps | Изменить runtime config и провести smoke test/rollback |

Конкретный вариант наставник выбирает при защите. Разрешены документация и привычные инструменты, помощь AI объявляется; попроси объяснить принятый diff. Не задавай головоломку, не связанную с выполненной работой.

Результат фиксируется как доказательство критериев задачи 06 и итоговых рекомендаций, без отдельного произвольного бонуса. При короткой практике защита ограничивается освоенными задачами.
