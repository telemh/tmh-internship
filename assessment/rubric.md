# Открытая шкала оценки

Цель практики — увидеть потенциал разработчика, а не максимальное число технологий за короткий срок. Для задачи учитываются артефакты, объяснение и способность исправлять замечания. Оценки кадрового характера не публикуются.

## Баллы за одну задачу

| Критерий | Максимум | Что является доказательством |
| --- | ---: | --- |
| Выполнение и корректность | 30 | Критерии приёмки выполнены; есть рабочий основной путь |
| Модель и инженерные решения | 20 | Разумные границы компонентов, валидация, объяснённые альтернативы |
| Проверки и обработка ошибок | 20 | Значимые негативные сценарии, воспроизводимые тесты |
| Понимание решения | 20 | Ответы 1–3 опросника с кодом/тестом, уточнения при обсуждении |
| Работа и оформление | 10 | Воспроизводимый README, review/исправления, прозрачная помощь |
| **Всего** | **100** | |

Для каждого критерия используй долю максимума: 0% — отсутствует; 25% — существенные пробелы; 50% — работает с заметной помощью/ограничениями; 75% — в основном самостоятельно, небольшие пробелы; 100% — объяснимо, воспроизводимо, крайние случаи учтены в пределах задания. Не требовать production-полноты там, где задача ограничена mock.

Опросник: 0–6 баллов по вопросам 1–3 переводятся в 0–20 как `round(20 * quiz / 6)`. Устное обсуждение подтверждает или корректирует эту часть, а не добавляет второй бонус. Вопрос 4 показывает умение видеть границы, отдельно не оценивается. Открытые ориентиры доступны, поэтому устная проверка обязательна для кадрового вывода.

Провал ключевого сценария или отсутствие понимания вопроса 1 возвращает задачу на доработку, даже если оформление хорошее. Нарушение правил данных сначала исправляется и разбирается с наставником; фактическая утечка обрабатывается по SECURITY.md. Балл не отменяет эти границы.

## Итог маршрута

Среднее по выполненным задачам, отдельно: первые 3 и последние 3, масштаб полученной помощи, качество исправлений и итоговая защита. Для короткого маршрута явно укажи, что задачи 04–06 не оценивались; не присваивай нули за невыданные задачи. Рост и самостоятельность важнее сравнения скорости с более опытным студентом.

| Ориентир полного маршрута | Решение для обсуждения lead |
| --- | --- |
| 80+ и самостоятельная защита | Рассмотреть следующий оплачиваемый/реальный этап работы |
| 65–79, есть рост | Рассмотреть продолжение с конкретным планом развития |
| 50–64 | Дополнительный учебный этап по выявленным пробелам |
| Менее 50 | Пока недостаточно оснований для самостоятельных рабочих задач |

Это рекомендованные ориентиры, не автоматический найм/отказ. Lead учитывает стартовый уровень, доступные часы, условия помощи и качество взаимодействия. Открыто сообщи студенту конкретные сильные стороны и следующий шаг.

Не оценивать количество строк, декоративность UI, количество библиотек, платные аккаунты, наличие дорогого GPU и процент coverage без содержания тестов. Использование AI разрешено; непонимание собственного решения оценивается как пробел понимания, а не как нарушение самого факта использования AI.
