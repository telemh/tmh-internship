# Технологическая рамка

Дата сверки: 2026-10-07. Это разрешённый для обучения обзор классов технологий, не схема рабочего развёртывания. Точные версии, настройки и внутренние компоненты продукта здесь не описываются.

| Область | Подтверждённые технологии компонентов ТМХ | Применение |
| --- | --- | --- |
| Мобильное приложение | Dart, Flutter | Интерфейс пациента, журнал, документы и взаимодействие с источниками измерений |
| Web | Vue 3, JavaScript / TypeScript | Кабинет специалиста и взаимодействие с backend |
| Основной backend | Bun, TypeScript / JavaScript, Elysia, GraphQL Yoga | API, обработка запросов и интеграции |
| Данные | MongoDB 8.0, MinIO / S3, Valkey | Документные данные, файлы, быстрые вспомогательные данные |
| Интеграции | REST, SOAP, webhook, SDK/Bluetooth; Health Connect, HealthKit, FCM | Обмен с МИС, устройствами, health-платформами и уведомления |
| AI-компоненты | Python, FastAPI, embeddings, FAISS; семейство multilingual-e5 | Поиск и RAG в отдельных AI-сервисах |
| Эксплуатация | Linux Debian/Ubuntu, systemd, Docker Compose, nginx, Sentry | Процессы, инфраструктурные сервисы, маршрутизация и диагностика |

Python/FastAPI не заменяет основной Bun-backend. AI/RAG — отдельное направление. PostgreSQL, React, Kubernetes и исследовательский rPPG не включены в обязательный маршрут: они не являются подтверждённой основой рассматриваемого типового решения.

## Учебные решения, не утверждения о внутреннем стеке

Vue Router, Pinia, Vitest, Playwright, pytest, JSON Schema, OpenAPI, GitHub Actions и прямой MongoDB driver используются как доступные средства обучения. Выбранные state management, router и HTTP-клиент Flutter — решение студента. Их наличие в методичке не означает, что именно они используются внутри ТМХ.

FHIR R4 предложен как дополнительный материал для понимания медицинского обмена, не как обязательный внутренний формат. BullMQ, LiveKit и конкретные cloud-сервисы не требуются для заданий. BLE, внешние уведомления и cloud-webhooks моделируются; доступ к кабинетам поставщиков не нужен.

## Версии и воспроизводимость

В своём решении зафиксируй версии runtime, SDK, пакетов и образов, сохрани lock-файлы. Для MongoDB используй ветку 8.0 и документацию этой ветки. Остальные версии выбирай из поддерживаемых совместимых выпусков и проверяй команды по официальным руководствам; номер «latest» не обеспечивает воспроизводимость.

MinIO остаётся частью контекста ТМХ. При этом публичный community-репозиторий MinIO помечен архивным с 25 апреля 2026 года и больше не сопровождается ([источник](https://github.com/minio/minio)). Поэтому в учебных задачах базовый путь — S3-адаптер с локальным mock; запуск конкретного S3-хранилища — дополнительная локальная практика по образу, который отдельно выбрал и проверил наставник. Задания не требуют устанавливать архивный бинарник или оформлять коммерческую лицензию.

Команды из текущей документации могут отличаться от версий твоего проекта. Укажи это в README, не меняй рабочие компоненты ТМХ для соответствия учебнику.
