# Публикация результата на личном GitHub

1. Создай публичный репозиторий, например `pulselab-mobile` или `pulselab-backend`. Основной учебный ресурс копировать целиком не нужно: скопируй нужные fixtures, контракты и шаблоны с указанием их происхождения.
2. Заполни README по `templates/student/README-template.md`. Укажи выбранное направление и редакцию задания.
3. Для каждой задачи создай ветку `task-01`, `task-02` и т. д. Оформляй PR в **свой** main. Сначала проверь работу, затем попроси наставника review; автор может объединить PR после обсуждения.
4. Сохраняй проверяемую историю: небольшие коммиты по смыслу, исправления review отдельными изменениями. Не делай единственный финальный upload всей работы.
5. Для задачи размести `docs/tasks/01-report.md`, `docs/tasks/01-answers.md` и ссылки на код, тесты, PR. Формат ID внутри отчёта: например `BE-01`.
6. Добавь `docs/ai-log.md` и отметь, в чём помог AI и как результат проверялся. Если AI не использовался, напиши это.
7. Перед сдачей повтори запуск в чистом окружении или из нового clone. Укажи ограничения и честный перечень ещё не реализованного.

Публичная ссылка на репозиторий обязательна. Для UI достаточно скриншотов или короткого видео на синтетических данных; публичный работающий backend и публикация приложения в store не требуются. Файлы БД, runtime-логи и локальные секреты не коммить.

Общие критерии: реализованы пункты задачи; есть осмысленные проверки ошибок; README воспроизводим; студент может объяснить код и внести небольшое изменение на защите. Процент coverage и число коммитов сами по себе не определяют оценку.
