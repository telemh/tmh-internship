# PulseLab: независимый учебный проект

PulseLab — вымышленный сервис для упражнений, не медицинское изделие и не интерфейс внутренних API ТМХ. Он хранит только синтетические измерения и не выдаёт диагнозы, рекомендации или клинические пороги.

## Сценарии

Пользователь смотрит журнал пульса и глюкозы, выбирает период, добавляет учебную запись и видит статус отправки. Специалист просматривает записи закреплённых учебных субъектов. Эмулятор устройства отправляет повторяющиеся и ошибочные события. Справка отвечает на вопросы об учебном приложении с указанием источника.

## Основные объекты

| Объект | Поля | Правило |
| --- | --- | --- |
| Subject | `id`, `label` | `s001` и `s002`, без ФИО и контактов |
| Reading | `id`, `subjectId`, `kind`, `value`, `unit`, `recordedAt`, `source`, `externalId` | Конкретная структура — в JSON Schema |
| Document metadata | `id`, `subjectId`, `filename`, `contentType`, `sizeBytes` | Только самостоятельно созданный учебный текст |
| Appointment | `id`, `subjectId`, `startsAt`, `status` | Только демонстрация экранов, отдельный API не обязателен |
| Knowledge document | `docId`, `title`, `text` | Справка о PulseLab, не клинические рекомендации |

`kind`: `heart_rate` или `glucose`. Для `heart_rate` единица `bpm`, для `glucose` — `mmol/L`. Значение — конечное число >= 0. Это техническое ограничение упражнения, не клиническая проверка нормы. `recordedAt` — RFC 3339 timestamp с часовым поясом; хранение/сравнение по UTC. Единицы никогда не смешиваются при агрегации. Все ID — строки.

Ключ идемпотентности импорта — `(subjectId, source, externalId)`. Новый ключ создаёт запись; повтор с тем же содержимым возвращает существующую; другое содержимое при том же ключе — конфликт. Сравниваются нормализованные поля payload без серверного `id`, время сравнивается по моменту UTC. Случайные дубли по значению и времени не удаляются.

## Учебный REST-контракт

Канонический машинный формат: [OpenAPI](../../shared/contracts/openapi.json). Перечень:

| Метод и путь | Назначение | Основные результаты |
| --- | --- | --- |
| `GET /health/live` | Процесс жив | 200 |
| `GET /health/ready` | Учебные зависимости готовы | 200 или 503 |
| `GET /api/v1/readings` | Список по `subjectId`, `kind`, `from`, `to`, `limit`, `offset` | 200; 401/403/422 |
| `POST /api/v1/readings` | Сохранение ReadingInput | 201 новый; 200 повтор; 409 конфликт; 401/403/422 |
| `POST /graphql` | Альтернативное чтение через Yoga | GraphQL data/errors, не копия REST-статусов |

Список отсортирован по `recordedAt DESC`, затем `id ASC`. Границы времени включительные; `from > to` — 422. `limit` по умолчанию 20, 1–100; `offset` по умолчанию 0, >= 0; `subjectId` обязателен. Ответ `{items, total, limit, offset}`; `total` — число после фильтрации до пагинации. Неизвестные параметры и поля — 422. Ошибка `{code, message, requestId}` без payload и секретов. Readiness не требует всех будущих компонентов: проверяет только включённые зависимости текущей задачи.

## Эмулятор доступа

До задачи по доступу API запускается только локально и использует fixtures. После неё локальный header `X-Lab-Actor` моделирует проверенную идентичность; это **не настоящая аутентификация**.

| Actor | Доступ |
| --- | --- |
| `patient-a` | Чтение/добавление для `s001` |
| `patient-b` | Чтение/добавление для `s002` |
| `doctor-a` | Чтение `s001`, без записи |
| Header отсутствует или неизвестен | 401 |

Другой субъект из учебной схемы или недопустимая операция — 403; неизвестный subjectId нарушает схему и даёт 422. Наличие role в UI не меняет серверную проверку. GraphQL использует тот же policy слой; forbidden выдаёт `errors` с `extensions.code=FORBIDDEN`, unauthenticated — `UNAUTHENTICATED`, invalid input — `BAD_USER_INPUT`.

## Независимость направлений

Mobile и frontend реализуют mock по контракту, а не ждут API другого студента. Интеграции используют своё локальное хранилище/приёмник. DevOps может начать с собственного минимального health-service. AI работает на `shared/knowledge/`; LLM заменяется детерминированным extractive/mock-ответом.

S3, уведомления, BLE и МИС не требуют внешних аккаунтов: нужен интерфейс и локальный эмулятор. Полноценный S3-стенд и настоящий BLE — дополнительные опции после основной сдачи.
