# FE-05 · Границы доступа и диагностические события

Направление: [Frontend · Vue 3 и TypeScript](../../README.md). Ориентир: 6–10 часов после изучения темы. Предыдущий шаг: FE-04.

## Цель

Корректно отобразить ограничения и очистить контекст при смене actor.

## Входные материалы

[PulseLab](../../../../docs/01-project/pulselab.md), [fixtures](../../../../shared/fixtures/README.md), [контракты](../../../../shared/contracts/README.md). Используй свой код предыдущего задания; внешний backend/аккаунт/оборудование не являются зависимостью.

## Сделать

Добавь учебное переключение patient-a/patient-b/doctor-a и fake API с policy. При смене actor очисти кеш и отменяй старые запросы. Ошибки отправляй в локальный fake sink с requestId без Reading payload.

Сначала опиши план из 3–5 шагов, затем реализуй минимальный путь и проверь ошибки. Если выбираешь другую библиотеку, объясни совместимость с технологией направления; замена основного стека требует согласования наставника.

## Критерии приёмки

- [ ] 403 не превращается в пустую таблицу; 401 предлагает выбрать учебный actor.
- [ ] При смене actor данные предыдущего контекста исчезают сразу и не возвращаются поздним ответом.
- [ ] UI-ограничение формы doctor-a согласовано с fake API, но не называется защитой сервера.
- [ ] Тест доказывает очистку state и отсутствие payload в sink; настоящие Sentry-ключи не нужны.
